## 0. 这套系统在做什么

工作台正上方装一台固定相机俯拍。工人装笔时，系统实时判断他**有没有按标准顺序装**，
一旦漏装、装错顺序、重复装、用错零件或者某步卡太久，当场报警并存档。

一帧画面的处理链路：

```
        ┌──────────────── 一帧图像 ────────────────┐
        │                                          │
        ▼                                          ▼
  YOLOv8n 零件检测                        MediaPipe 手部关键点
  「画面里有笔杆、弹簧、笔芯…                「手的 21 个关节在哪」
   各自在什么位置」                                 │
        │                                          │
        └────────────────┬─────────────────────────┘
                         ▼
              298 维特征向量（每帧一个）
              手的位置 + 姿态 + 速度 + 加速度 + 手离各零件多远
                         │
                         ▼
              攒够 16 帧 → Bi-LSTM 神经网络
                         │
                         ▼
        7 类动作之一：拿取 对准 插入 旋拧 按压 放置 闲置
                         │
                         ▼
              状态机拿这个动作去比对 SOP 模板
              「现在应该装弹簧，你却在装笔芯」
                         │
                         ▼
              合格 ／ 6 类异常 → 界面 + 数据库
```

**为什么要分成「动作识别」和「顺序判定」两层？** 因为神经网络只擅长回答「这 0.64
秒里手在做什么动作」，不擅长记住「已经装了几步、下一步该装什么」。后者是确定性
规则，交给状态机，改 SOP 只要改一个 JSON 文件，不用重新训练模型。

**七类动作**（这是模型的输出，也是标注时要打的标签）：

| 英文 | 中文 | 什么样 |
|---|---|---|
| `Pick` | 拿取 | 手移到零件上方 → 手指合上 → 手和零件一起抬起 |
| `Align` | 对准 | 手持零件在目标上方小幅来回微调 |
| `Insert` | 插入 | 手持零件沿轴向匀速下压进腔体 |
| `Screw` | 旋拧 | 手腕绕轴转，拇指食指间距周期性变化 |
| `Press` | 按压 | 沿轴向快速短距下压 → 停顿 → 松开 |
| `Place` | 放置 | 手和成品移到目标区 → 手指张开 → 手撤回 |
| `Idle` | 闲置 | 手不在工作区，或者静止不动 |

**六类异常**（这是系统的输出）：

| 代号 | 中文 | 触发条件 |
|---|---|---|
| `MISSING_STEP` | 漏装 | 某个必做步骤被跨过 |
| `WRONG_ORDER` | 错序 | 顺序和 SOP 不符 |
| `EXTRA_STEP` | 多装 | 重复执行已完成的步骤 |
| `WRONG_PART` | 零件错误 | 用了不该用的零件，或前置零件不在画面里 |
| `TIMEOUT` | 超时 | 某步耗时超过模板设定的限时 |
| `DROPPED` | 零件掉落 | 零件从工作区消失（依赖零件检测） |

## 1. 环境准备

**这一步要干什么**：把代码和依赖装好。
**做完能得到什么**：`python run.py --selfcheck` 全绿。

### 1.1 硬件

**只是想先跑通流程看看效果**：普通笔记本就够，没有独立显卡也行，CPU 能跑，只是训练慢。

**正式上产线**：参考设计文档 §6.5 的推荐配置。

| 部件 | 推荐 | 说明 |
|---|---|---|
| 显卡 | NVIDIA RTX 3060 12GB 或 4060 8GB | 一张卡够 4～6 路视频 |
| CPU | Intel i5-13500 / AMD Ryzen 5 7600 | 6 核 12 线程 |
| 内存 | 16GB | 三个模型常驻约 3GB |
| 硬盘 | 512GB NVMe SSD | 历史视频建议另外存 NAS |
| 相机 | USB 或网络相机，≥25fps，≥960×544 | **俯视固定机位**，装稳别晃 |

**相机怎么装（很重要，装错了后面全白干）**：

- **正上方俯拍**，镜头对着工作台面，和台面尽量平行
- 装**牢固**，不能晃。一晃动，帧间速度特征就全是噪声
- 全部零件和双手都要在画面内，不要被工人身体挡住
- 光照**均匀稳定**，别让工人的影子扫过零件区
- 装好之后就**别再动了**。挪了相机等于换了场景，模型精度会掉，得重新采数据

### 1.2 Python 版本（最容易踩的坑）

**必须是 Python 3.10、3.11 或 3.12。**

MediaPipe（提取手部关键点的库）目前**没有 3.13 和 3.14 的安装包**，用这两个版本会在
`pip install` 时直接失败。

先查一下你的版本：

```bash
python3 --version
```

如果不是 3.10～3.12，去 [python.org/downloads](https://www.python.org/downloads/)
装一个 3.11。装完之后用 `python3.11` 这个名字调用它（Windows 上是 `py -3.11`）。

### 1.3 下载与安装

```bash
git clone git@github.com:zniihgnexy/SOP_detection_system_demo.git
cd SOP_detection_system_demo

python3.11 -m venv .venv
source .venv/bin/activate          # Windows 用：.venv\Scripts\activate

pip install -r requirements.txt
```

> **虚拟环境是什么**：`.venv` 是一个只属于这个项目的独立 Python 环境，装的包不会污染
> 系统。**每次开新终端都要重新执行一次 `source .venv/bin/activate`**，否则会提示找不到
> 模块。看到命令行提示符前面有 `(.venv)` 就说明激活成功了。

装依赖大概要几分钟（torch 比较大）。如果卡在下载，国内可以换镜像：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 1.4 自检

```bash
python run.py --selfcheck
```

它会逐项检查并告诉你缺什么：

```

    ✓ mediapipe    手部关键点
    ✓ ultralytics  YOLOv8n 零件检测
    ✓ fastapi      Web 界面

  配置文件：
    ✓ configs/gelpen_0.5.json
    ...

  判定层：
    ✓ SOP 模板 GelPen_0.5mm 载入正常，6 个步骤，标准序列判定为 PASS
```

## 2. 五分钟跑通判定层

**这一步要干什么**：在完全没有数据和模型的情况下，先确认「顺序判定」这套逻辑是好的。
**做完能得到什么**：看到系统当场揪出漏装、错序、超时。

系统分两半：**看画面**（要训练）和**判顺序**（纯逻辑，不用训练）。
这一章跳过前一半，直接给判定层喂手写的动作序列。

```bash
python run.py --replay configs/demo_sequence.json
```

输出（截取「漏装弹簧」那一段）：

```
【2/4】漏装弹簧
  期望结果：FAIL / MISSING_STEP
  跳过 S2 装弹簧直接装笔芯。判定引擎在装笔芯那一刻就能发现 S2 被跨过。

    ✓   0.4s  S1 取笔杆     耗时   400ms  置信度 0.95
    ✗   2.6s  MISSING_STEP  漏装：步骤 S2 装弹簧 被跳过
    ✓   2.6s  S3 装笔芯     耗时  2200ms  置信度 0.94
    ✓   4.2s  S4 装笔尖     耗时  1600ms  置信度 0.9
    ✓   5.6s  S5 装笔帽     耗时  1400ms  置信度 0.95
    ✓   6.4s  S6 放置成品    耗时   800ms  置信度 0.97
  ──────────────────────────────────────────────────────────
  ✓ 结果：FAIL  异常：MISSING_STEP  总耗时 6.4s  已入库 #2
```

四个示例分别演示正常装配、漏装、错序、超时。最后会汇总每个用例是否符合预期。

`configs/demo_sequence.json` 就是这四个序列，**你可以直接改它**试自己的场景：改动作
顺序、删掉某一步、把时间间隔拉长制造超时，再跑一遍看系统怎么判。这是理解判定逻辑
最快的办法，而且不消耗任何算力。

> **关于「错序」为什么报两条异常**：第 3 个示例（先装笔尖后装笔芯）会同时报
> `MISSING_STEP` 和 `WRONG_ORDER`。这不是 bug。系统是**在线**判断的：装笔尖那一刻，
> 它只知道笔芯被跨过了（漏装）；等笔芯后来补上，才能确认是顺序颠倒（错序）。
> 未来的事情当时确实不知道。

## 3. 第一步：采集视频

**这一步要干什么**：录下工人装笔的过程，作为训练素材。
**做完能得到什么**：`data/videos/` 里一堆 mp4。

### 3.1 建目录

```bash
mkdir -p data/videos data/annotations data/pen_parts models
```

### 3.2 录多少

设计文档 §7 Phase 1 的目标量：

| 类型 | 目标数量 | 具体内容 |
|---|---|---|
| 正样本（装对的） | ≥ 200 段 | 每段一个完整装配周期，从拿笔杆到放成品 |
| 负样本 · 漏装 | 30 段 | 故意跳过弹簧或笔芯 |
| 负样本 · 错序 | 30 段 | 故意先装笔尖再装笔芯 |
| 负样本 · 多装 | 20 段 | 故意重复装某一步 |
| 负样本 · 零件错误 | 20 段 | 故意用错规格的零件 |

**如果你只是想先看到东西跑起来**，不用凑够这个量。**30 段正样本 + 每类异常 5 段**
就能训出一个能动的模型，只是准确率到不了 92% 的验收线。先跑通全流程，再补数据
重训 —— 这比一次性攒够两百段再开始要靠谱得多。

负样本必须**真的去演**，不能只录正样本。模型没见过错的样子，就学不会区分对错。

### 3.3 录的时候注意

- 相机位置**全程不变**（第 1.1 节）
- 一段视频只装一支笔，从「手伸进画面」到「成品放下」
- 让**不同工人**都录一些，手速快慢都要有，否则模型只认一个人的习惯
- 别剪辑、别加速、别裁剪画面
- 文件名带上工位和日期，比如 `station01_20260715_001.mp4`
- 存到 `data/videos/`

## 4. 第二步：标注

**这一步要干什么**：告诉模型「画面里哪个框是弹簧」和「这几帧手在做什么动作」。
**做完能得到什么**：`data/pen_parts/` 里的零件框标注 + `data/annotations/` 里的动作标注。

这是整个项目最费人力的一步。两种标注互相独立，可以两个人同时做。

### 4.1 零件框标注（给 YOLO 用）

**目标**：在图片上把每个零件框出来，≥ 10000 个框。

**工具**：[Label Studio](https://labelstud.io/)（网页版，推荐）或
[LabelImg](https://github.com/HumanSignal/labelImg)（桌面版，更简单）。
导出格式选 **YOLO**。

**六个类别，名字必须一字不差**（顺序也不能变，序号就是下面的 0～5）：

| 序号 | 类别名 | 中文 |
|---|---|---|
| 0 | `barrel` | 笔杆 |
| 1 | `cap` | 笔帽 |
| 2 | `spring` | 弹簧 |
| 3 | `refill` | 笔芯（墨水管） |
| 4 | `tip` | 笔尖锥套 |
| 5 | `grip` | 握胶 |

**不用每一帧都标**。从视频里每隔 10～20 帧抽一张图来标就够了，抽 500～1000 张、
平均每张 10～20 个框，就能凑到一万框。

**目录必须严格长这样**（YOLO 靠目录名找数据，错一个字母就报 Dataset not found）：

```
data/pen_parts/
├── images/
│   ├── train/     001.jpg  002.jpg  ...     ← 70%
│   ├── val/       ...                        ← 15%
│   └── test/      ...                        ← 15%
└── labels/
    ├── train/     001.txt  002.txt  ...     ← 与图片同名，只是扩展名不同
    ├── val/       ...
    └── test/      ...
```

`001.txt` 里每行一个零件，五个数字用空格隔开：

```
0 0.4521 0.3810 0.2604 0.0735
2 0.6198 0.5147 0.0521 0.0294
```

含义是 `类别序号 中心x 中心y 宽 高`，后四个都是**相对图片尺寸的 0～1 小数**。
标注工具导出 YOLO 格式时会自动算好，你不用手写。

### 4.2 动作标签标注（给 Bi-LSTM 用）

**目标**：标出每段视频里每个动作的起止帧，≥ 50000 帧。

**每段视频写一个 JSON**，放到 `data/annotations/`，文件名随意（建议和视频同名）。
格式如下 —— 可以直接复制改：

```json
{
  "video": "station01_20260715_001.mp4",
  "fps": 25,
  "total_frames": 375,
  "annotations": [
    { "frame_range": [0, 75],    "action": "Idle" },
    { "frame_range": [76, 110],  "action": "Pick",   "target_part": "barrel" },
    { "frame_range": [111, 145], "action": "Pick",   "target_part": "spring" },
    { "frame_range": [146, 180], "action": "Insert", "target_part": "spring" },
    { "frame_range": [181, 215], "action": "Insert", "target_part": "refill" },
    { "frame_range": [216, 260], "action": "Screw",  "target_part": "tip" },
    { "frame_range": [261, 300], "action": "Press",  "target_part": "cap" },
    { "frame_range": [301, 340], "action": "Place",  "target_part": "finished_pen" },
    { "frame_range": [341, 374], "action": "Idle" }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `video` | 是 | 视频文件名，相对 `data/videos/` |
| `total_frames` | 是 | 总帧数。不填的话会按最大 frame_range 推算 |
| `frame_range` | 是 | `[起始帧, 结束帧]`，**两端都包含** |
| `action` | 是 | 七类动作之一，大小写要对：`Pick` `Align` `Insert` `Screw` `Press` `Place` `Idle` |
| `target_part` | 否 | 填了方便你自己复核。**训练动作模型时不使用它** —— 动作模型只预测动作类别，检测时「操作的是哪个零件」由 YOLO 现场判断 |
| `fps` | 否 | 记录用，程序不读 |

**没被任何 `frame_range` 覆盖的帧会自动记成 `Idle`**，所以工人手不在画面里的那些
片段不用专门标。

**怎么找到帧号**：用支持逐帧的播放器，比如
[VLC](https://www.videolan.org/)（`E` 键逐帧前进）或
[Label Studio 的视频时间轴标注](https://labelstud.io/tag/video)。
25fps 的视频，第 3.0 秒就是第 75 帧。

**标注要点**：

- 边界不用精确到帧。差 2～3 帧没关系，因为模型是按 16 帧一个窗口来看的
- `Pick` 从「手开始朝零件移动」算起，到「零件被抬离台面」为止
- `Insert` / `Screw` / `Press` 三个动作要**认真区分**，它们决定 SOP 判定的准确性。
  弹簧笔芯是插进去（Insert），笔尖是拧上去（Screw），笔帽是按下去（Press）
- 拿不准的片段标 `Idle`，比标错一个具体动作危害小

### 4.3 关于数据集划分

零件检测要你**手动**分 train/val/test（第 4.1 节的目录）。

动作识别**不用手动分**，`train_action.py` 会自动按 70/15/15 划分。注意它是
**按视频**划分而不是按帧划分 —— 相邻的两个 16 帧窗口共享 14 帧，如果按窗口随机切，
验证集里就会混进训练集看过的画面，跑出来的准确率是虚高的，上产线立刻打脸。

## 5. 第三步：训练零件检测模型

**这一步要干什么**：让模型学会在画面里找到六种零件。
**做完能得到什么**：`models/pen_parts.pt`。

### 5.1 填数据集路径

打开 `configs/pen_parts_dataset.yaml`，把 `path:` 改成**绝对路径**。
先运行这行拿到路径：

```bash
python -c "import pathlib; print(pathlib.Path('data/pen_parts').resolve())"
```

把输出（形如 `/Users/you/SOP_detection_system_demo/data/pen_parts`）粘到 `path:` 后面。

> **为什么非要绝对路径**：Ultralytics 解析相对路径时，是相对它自己的
> `datasets_dir`（默认 `~/datasets`），不是相对这个 yaml 文件。写相对路径会报
> `Dataset not found`，而且报错信息里的路径看起来莫名其妙。

### 5.2 训练

```bash
yolo detect train model=yolov8n.pt data=configs/pen_parts_dataset.yaml \
  epochs=100 imgsz=544 batch=16 lr0=0.001 lrf=0.01 optimizer=AdamW \
  hsv_h=0.015 hsv_s=0.3 hsv_v=0.2 degrees=5 translate=0.1 scale=0.3
```

超参来自设计文档 §7 Phase 2.1。后面那些 `hsv_*` / `degrees` 是数据增强：色调只小幅
扰动（零件颜色是固定的），旋转只给 5 度（相机是固定机位），缩放给 0.3（模拟零件远近）。

有独立显卡的话几十分钟到两小时；纯 CPU 会慢很多，可以先把 `epochs` 降到 20 试通流程。

### 5.3 检查结果并放到位

训练完，终端会打印 `mAP50` 和 `mAP50-95`。**验收线是 mAP@0.5 ≥ 0.90**。

达标了就把权重复制过来：

```bash
cp runs/detect/train/weights/best.pt models/pen_parts.pt
```

> 路径里的 `train` 可能是 `train2`、`train3`……多跑几次会递增，看终端最后打印的
> `Results saved to` 那一行是哪个目录。

**没达标怎么办**：

- mAP 只有 0.5～0.8 → 标注量不够，继续标，尤其补弹簧、笔芯这类小目标
- 某一类特别差 → 那类的框太少或者标得不一致，重点补
- 训练集好验证集差 → 过拟合，说明视频场景太单一，换工人、换时段多录一些

## 6. 第四步：训练动作识别模型

**这一步要干什么**：让模型学会识别七类装配动作。
**做完能得到什么**：`models/action_model.pt`。

**必须先完成第 5 章**，因为抽特征时要用到零件检测的结果。

### 6.1 训练

```bash
python scripts/train_action.py --yolo models/pen_parts.pt
```

一条命令做完四件事：

1. **抽特征**：对每段视频逐帧跑 YOLO + MediaPipe，算出 298 维特征。
   这一步最慢（一段 15 秒的视频大概要十几秒），结果会缓存到 `data/cache/`
2. **切数据集**：按视频 70/15/15
3. **训练**：AdamW、余弦退火、5 epoch 预热、Focal Loss、早停
4. **评估并保存**：存权重，导出 ONNX

> **第二次运行会快很多**，因为特征已经缓存。所以调超参不用重复抽特征。
> 改了标注 JSON 之后缓存会自动失效重算。

### 6.2 看结果

```
在 test 集上评估：

  总体准确率 93.47%   （§7 Phase 2 验收线 ≥ 92%）

  各类召回率（验收线 > 88%）：
    ✓ Pick     94.20%
    ✓ Align    89.51%
    ✓ Insert   92.83%
    ✗ Screw    81.04%
    ✓ Press    90.12%
    ✓ Place    95.66%
    ✓ Idle     97.31%

  混淆矩阵（行=真实，列=预测）：
           Pick Alig Inse Scre Pres Plac Idle
    Pick    891    12    9    2    4    3   18
    Align    21   402    31    5    2    1    9
    ...
```

**混淆矩阵怎么看**：第 `Screw` 行第 `Press` 列的数字很大，说明模型经常把「旋拧」认成
「按压」。对策就是补这两个动作的标注，或者检查标注时是不是自己也把两者混了。

**准确率没到 92%**：脚本退出码会是 1。常见原因和对策：

| 现象 | 原因 | 对策 |
|---|---|---|
| 整体都低（< 80%） | 数据太少 | 补视频，尤其补负样本 |
| `Idle` 很高、其他都低 | 类别不平衡没压住 | 加大 `--gamma`，比如 `--gamma 3.0` |
| 训练损失一直降、验证不降 | 过拟合 | 补数据；或者减小 `--epochs` |
| 某两类互相混 | 标注本身不一致 | 回去统一标注口径 |

调参可以直接加参数，不用改代码：

```bash
python scripts/train_action.py --yolo models/pen_parts.pt --gamma 3.0 --epochs 200
```

全部可调参数用 `python scripts/train_action.py --help` 看。

## 7. 第五步：写自己的 SOP 模板

**这一步要干什么**：告诉系统你的笔「标准装配顺序」是什么。
**做完能得到什么**：一个 `configs/你的笔型.json`。

仓库自带 `configs/gelpen_0.5.json`（中性笔 0.5mm）。换笔型就复制一份改：

```bash
cp configs/gelpen_0.5.json configs/my_pen.json
```

### 7.1 字段逐个解释

顶层：

| 字段 | 说明 |
|---|---|
| `model_name` | 笔型名，会显示在界面上，也用来在数据库里区分 |
| `version` | 版本号。改了流程建议升版本，这样历史记录能对上当时用的是哪版 |
| `initial_parts` | 开工前台面上应该有哪些零件 |
| `final_parts` | 装完之后应该有什么（成品） |
| `steps` | **有序**的步骤列表，顺序就是标准顺序 |

每个步骤：

| 字段 | 说明 |
|---|---|
| `id` | 步骤编号，界面和告警里显示这个，不能重复 |
| `name` | 中文步骤名，界面上显示 |
| `expected_action` | 这一步该做什么动作，七类之一 |
| `target_part` | 这一步操作哪个零件，六类零件名之一（最后一步可以写 `finished_pen`） |
| `parent_part` | 装到哪个零件上。记录用，判定时不强制 |
| `timeout_ms` | 这一步的限时（毫秒）。超了报 `TIMEOUT` |
| `required_parts_present` | 做这一步之前，画面里必须能看到哪些零件。少了报 `WRONG_PART` |
| `optional` | `true` 表示可选步骤，跳过不算异常 |

### 7.2 一个例子

自带模板的六步是：

| 步骤 | 名称 | 动作 | 零件 | 限时 |
|---|---|---|---|---|
| S1 | 取笔杆 | `Pick` | `barrel` | 3000ms |
| S2 | 装弹簧 | `Insert` | `spring` | 5000ms |
| S3 | 装笔芯 | `Insert` | `refill` | 5000ms |
| S4 | 装笔尖 | `Screw` | `tip` | 6000ms |
| S5 | 装笔帽 | `Press` | `cap` | 4000ms |
| S6 | 放置成品 | `Place` | `finished_pen` | 3000ms |

**注意只有「装配动作」才算一个步骤。** 中间那些「拿起弹簧」「对准笔芯」的动作，
系统会识别但不推进状态机，也不会因为它们报异常 —— 否则工人稍微调整一下拿法就会
误报。真正决定装配顺序的是插入、旋拧、按压、放置这几个提交性动作。

### 7.3 限时怎么定

先按第 8 章跑几十支正常装配，然后查每步实际耗时：

```bash
sqlite3 sop.db "SELECT result, duration_ms FROM detection_records ORDER BY id DESC LIMIT 30;"
```

设计文档建议取**平均值 + 2 倍标准差**。定太紧会一直误报超时，定太松就抓不到真卡壳。
一开始宁可放宽一点，跑顺了再收紧。

### 7.4 改完验证一下

```bash
python run.py --replay configs/demo_sequence.json --sop configs/my_pen.json
```

这样能确认 JSON 没写错（字段拼错、动作名大小写错、id 重复都会当场报出来）。
示例序列是按自带模板写的，换成你的模板后判定结果大概会变成 FAIL —— 这正常，
这里只是验证模板本身合法。

## 10. 检测记录在哪、怎么导出

记录存在 SQLite 文件里，默认是仓库根目录的 `sop.db`（用 `--db` 可以改位置）。

三张表：

| 表 | 内容 |
|---|---|
| `sop_templates` | 用过的 SOP 模板，含完整 JSON 快照 |
| `sop_step_details` | 模板展开成一行一步，方便直接写 SQL 查 |
| `detection_records` | 每次装配的结果 |

### 常用查询

```bash
# 最近 20 次装配
sqlite3 sop.db "SELECT id, timestamp, result, anomaly_type FROM detection_records ORDER BY id DESC LIMIT 20;"

# 今天的合格率
sqlite3 sop.db "SELECT COUNT(*) AS 总数, SUM(result='PASS') AS 合格 FROM detection_records WHERE timestamp LIKE date('now')||'%';"

# 异常类型排行
sqlite3 sop.db "SELECT anomaly_type, COUNT(*) FROM detection_records WHERE result='FAIL' GROUP BY anomaly_type ORDER BY 2 DESC;"

# 导出成 Excel 能打开的 CSV
sqlite3 -header -csv sop.db "SELECT * FROM detection_records;" > records.csv
```

> 没有 `sqlite3` 命令的话：macOS 自带；Ubuntu 用 `sudo apt install sqlite3`；
> Windows 去 [sqlite.org/download.html](https://www.sqlite.org/download.html) 下
> `sqlite-tools`。也可以用图形工具 [DB Browser for SQLite](https://sqlitebrowser.org/)
> 直接双击打开 `sop.db`。

界面上的检测记录表和合格率就是从这三张表读的，接口是 `/api/v1/records` 和
`/api/v1/stats/overview`，要对接你自己的系统可以直接调。

## 11. 排错表

### 装环境阶段

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `pip install` 报找不到 mediapipe 的版本 | Python 是 3.13 或 3.14 | 换 3.10～3.12，见 1.2 节 |
| `ModuleNotFoundError: No module named 'sop'` | 不在仓库根目录运行 | `cd` 到仓库根目录再跑 |
| `ModuleNotFoundError: No module named 'cv2'` | 虚拟环境没激活 | 重新 `source .venv/bin/activate`，提示符要有 `(.venv)` |
| 下载依赖一直超时 | 网络 | 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |

### 训练阶段

| 现象 | 原因 | 怎么办 |
|---|---|---|
| YOLO 报 `Dataset not found` | yaml 里 `path` 是相对路径 | 改成绝对路径，见 5.1 节 |
| YOLO 找不到标签 | 目录结构不对 | 严格按 4.1 节的 `images/` `labels/` 分开放 |
| `data/annotations 里没有标注文件` | 还没做第 4.2 节 | 先标注动作 |
| `找不到零件检测权重` | 第 5 章没做完 | 先训 YOLO 并 `cp` 到 `models/pen_parts.pt` |
| `标注里的动作 'xxx' 不是 7 类之一` | 动作名拼错或大小写错 | 必须是 `Pick` `Align` `Insert` `Screw` `Press` `Place` `Idle` |
| 抽特征特别慢 | 正常，YOLO 逐帧跑 | 第二次会读缓存；也可以先拿少量视频试通 |
| 显存不够 `CUDA out of memory` | batch 太大 | 加 `--batch-size 32` 或 `16` |

### 检测阶段

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `找不到动作识别模型` | 第 6 章没做完 | 先训练；只想看判定逻辑就用第 2 章的 `--replay` |
| 界面打开是空白 | 视频源没打开 | 看终端有没有报错；确认视频路径或摄像头编号 |
| 界面显示「连接断开，重连中」 | 后台采集线程挂了 | 看终端报错信息 |
| 画面正常但步骤一直不推进 | 动作识别一直输出 `Idle` 或置信度低于 0.6 | 模型精度不够，回第 6 章补数据重训 |
| 步骤乱跳、频繁误报 | 模型把动作认错了 | 看第 6.2 节的混淆矩阵定位是哪两类混了 |
| 一直报 `WRONG_PART` | 零件检测漏了必需零件 | 检查零件是否被手挡住；或 YOLO 精度不够 |
| 一直报 `TIMEOUT` | 模板限时太紧 | 按 7.3 节重新定限时 |
| 摄像头打不开 | 被别的程序占用 / 没授权 | 关掉其他用摄像头的软件；macOS 要在系统设置里给终端授权 |

### 想确认是代码问题还是数据问题

```bash
pytest -q
```

92 个用例。全绿说明代码本身没问题（判定层、特征工程、界面状态都被覆盖了），
那问题就在数据或模型上。没装 torch/opencv 的机器会自动跳过对应用例。

## 12. 这个 demo 不做什么

说清楚边界，免得你花时间找不存在的功能。

### 刻意简化掉的（设计文档里有，这里用更轻的方案代替）

| 设计文档 | 这里的做法 | 为什么 |
|---|---|---|
| PostgreSQL + Redis | SQLite 单文件 | 表结构一样，但零配置、免起服务 |
| 7 个 Docker 服务 | 单进程 | 单工位没有拆服务的必要 |
| Vue 3 SPA + 拖拽式 SOP 编辑器 | 单页原生 HTML；SOP 改 JSON | 编辑器本身比整个检测逻辑还大 |
| TensorRT / OpenVINO / NCNN | PyTorch，附 ONNX 导出 | 换后端是精度达标之后的优化 |
| 多工位并行 | 单工位 | 多工位就是多起几个进程，各用一个 `--station` 和 `--db` |

### 没有实现的

- **告警推送**：企业微信、钉钉、短信、声光报警、PLC 停线联动。异常只落终端和数据库
- **MES 系统对接**：不拉工单、不回传质量数据
- **用户与权限**：界面没有登录，任何能访问端口的人都能看（所以别开到公网）
- **DTW 自动生成 SOP 模板**：模板得手写，见第 7 章
- **零件掉落检测**：`DROPPED` 这个异常类型定义了但没有触发逻辑，需要跨帧的零件追踪
- **Transformer 版动作模型**：设计文档把它列为 Bi-LSTM 不达标时的备选，没实现

### 设计文档里自相矛盾、由本实现拍板的地方

设计文档有 6 处前后不一致。每一处的取法都写在对应代码文件的注释里，这里汇总：

| # | 矛盾点 | 本实现的取法 | 在哪 |
|---|---|---|---|
| 1 | 298 维按单手推算，但 MediaPipe 配了双手 | **取单手**（置信度最高那只为主操作手）。因为 298 这个数字被模型输入、ONNX 形状、延迟表反复引用，改双手要连带推翻三处 | `sop/features.py` |
| 2 | 步骤编号语义不一致（状态图里是「已完成」，界面里是「进行中」） | 采用**动作粒度**编号，共 6 步。依据是设计文档 §4.3.4 的表、§8.3.2 的进度条、§8.3.3 的编辑器三处一致 | `sop/fsm.py` |
| 3 | 一个步骤配一个动作，但状态图里一条边消耗两个动作 | 中间的 `Pick` 归为**过渡动作**，不推进状态机也不报异常 | `sop/fsm.py` |
| 4 | 判定逻辑调用了 7 个模板方法，但数据结构里没定义 | 全部实现在 `SOPTemplate` 上 | `sop/fsm.py` |
| 5 | 32 维零件类别嵌入没说怎么算 | 最近 4 个零件各一个 6 类 one-hot（24 维）+ 各自置信度（4 维）+ 补 4 个零。**不**从 YOLO 内部取 embedding，那会破坏「298 维是纯预处理输出」这个边界 | `sop/features.py` |
| 6 | 界面有权限管理页，接口列表里没有对应端点 | 不做认证，文档明确写只在内网用 | 本章上一节 |

另外两处对训练的取舍：

- **损失函数**只实现了 Focal Loss，跳过了 Center Loss 和时序平滑损失。前者是精度调优
  手段，在还没有基线的阶段没意义；后者约束「相邻帧标签一致」，但本模型一个窗口只输出
  一个标签，且训练时窗口是打乱的，这一项无法正确表达
- **数据增强**只做了关键点抖动、时间缩放、Mixup。时间裁剪和时间缩放作用重叠；手部平移
  的效果已被「相对手腕坐标」这组特征抵消；水平翻转只在相机镜像安装时才对
