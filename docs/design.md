## 一、项目背景

在笔类产品装配生产线上，装笔顺序的准确性直接影响产品质量和生产效率。目前产线主要依赖人工目视检查或抽查来验证装配顺序，存在以下问题：

- 人工检测效率低，无法实现100%全检
- 检测标准不统一，依赖工人经验和注意力
- 异常发现滞后，不良品已批量产生后才被察觉
- 缺乏可追溯的检测记录，质量问题难以回溯

基于计算机视觉与深度学习技术，构建一套**装笔顺序SOP智能检测系统**，实现对装配过程的实时监控、自动检测与异常告警，是提升产线智能化水平的迫切需求。

## 三、系统总体设计

### 3.1 系统架构

系统采用模块化分层架构，自上而下分为以下五个层次：

```
┌─────────────────────────────────────────────────────────┐
│                    展示与交互层                          │
│    [监控大屏]    [管理终端]    [移动端推送]              │
├─────────────────────────────────────────────────────────┤
│                    业务逻辑层                            │
│    [SOP规则引擎]  [判定引擎]  [告警服务]  [数据服务]     │
├─────────────────────────────────────────────────────────┤
│                  视觉分析引擎层（核心）                  │
│    [目标检测]  [动作识别]  [时序建模]  [异常检测]        │
├─────────────────────────────────────────────────────────┤
│                   图像预处理层                           │
│    [去噪]  [ROI]  [光照补偿]  [帧采样]                   │
├─────────────────────────────────────────────────────────┤
│                    视频采集层                            │
│    [工位1相机]  [工位2相机]  ...  [工位N相机]            │
└─────────────────────────────────────────────────────────┘
```

#### （1）视频采集层

- 通过工业相机（USB / GigE / IP Camera）实时采集装配工位的视频流
- 支持多工位并行接入，每个工位独立采集
- 帧率 ≥ 25fps，分辨率 ≥ 960×544，确保动作捕捉的完整性

#### （2）图像预处理层

- **图像去噪**：高斯滤波/中值滤波消除传感器噪声
- **ROI提取**：裁剪出工作区域，排除无效背景
- **光照补偿**：直方图均衡化，消除环境光照波动影响
- **帧采样**：根据动作速度自适应调整采样间隔

#### （3）视觉分析引擎层（核心）

- **目标检测模块**：识别并定位工作台上的各类笔零件和手部位置
- **动作识别模块**：检测装配动作类型（拿取、插入、旋拧、放置等）
- **时序建模模块**：构建装配步骤的时间序列，与标准SOP匹配比对
- **异常检测模块**：识别顺序错误、遗漏步骤、多余动作等异常

#### （4）业务逻辑层

- **SOP模板管理**：定义和维护标准装配顺序规则库
- **实时判定引擎**：将检测到的装配序列与SOP规则进行实时比对
- **告警推送**：检测到异常时即时推送告警信息
- **数据记录**：完整记录每次装配的过程数据和检测结果

#### （5）展示与交互层

- **实时监控大屏**：显示各工位状态、装配进度、检测结果
- **历史查询**：支持按时间、工位、批次等维度检索检测记录
- **统计分析**：装配合格率、常见错误类型分布、趋势分析
- **系统配置**：SOP规则编辑、检测灵敏度调节、权限管理

## 四、核心功能模块详细设计

### 4.1 零件目标检测模块

**功能**：实时识别并定位工作台上的各类笔零件。

**技术方案**：
- 基于 YOLOv8 / YOLOv11 或 RT-DETR 等轻量级目标检测模型
- 检测类别：笔杆、笔帽、弹簧、笔芯（墨水管）、笔尖锥套、握胶等
- 模型需针对实际产线数据进行微调（Fine-tuning）
- 输出：每个零件的类别、边界框坐标 (x, y, w, h)、置信度

**检测逻辑**：

1. **零件存在性检测** — 确认当前帧中出现了哪些零件
2. **零件位置追踪** — 跟踪零件在工作台上的坐标变化
3. **零件状态判定** — 零件是否被手持 / 是否已装配 / 是否在原位
4. **手部检测** — 识别手部/手指的位置和姿态

### 4.2 装配动作识别模块（方案A：时序关键点 + LSTM/Transformer）

> **选型理由**：方案A在精度与推理速度之间取得最佳平衡。手部关键点序列天然构成时序特征，LSTM/Transformer可直接建模动作的时间依赖关系，无需昂贵的3D卷积计算。同时关键点特征维度极低（21点 × 3维 = 63维/帧），推理延迟可控在 5ms 以内。

#### 4.2.1 动作类别定义

| 动作 | 英文 | 说明 | 关键视觉特征 |
|------|------|------|-------------|
| 拿取 | Pick | 手从工作台拿起某个零件 | 手部从初始位移动到零件上方→手指闭合→手+零件共同上移 |
| 对准 | Align | 将一个零件对准另一个零件的接口 | 手持零件在目标上方微调位置，小幅度往复运动 |
| 插入 | Insert | 将零件插入另一个零件的腔体 | 手持零件沿轴向直线下移，速度均匀 |
| 旋拧 | Screw | 旋转零件完成螺纹连接 | 手腕绕轴旋转，拇指-食指间距离周期性变化 |
| 按压 | Press | 施加压力完成卡扣/过盈配合 | 手持零件沿轴向快速短距下移→停顿→释放 |
| 放置 | Place | 将装配好的组件放回工作台或成品区 | 手+零件移动到目标区域→手指张开→手部撤回 |
| 闲置 | Idle | 无装配动作，等待或过渡 | 手部在工作区外或静止不动 |

#### 4.2.4 特征工程详细设计

滑动窗口长度 **N = 16帧**（约 0.64秒 @25fps），步长 **stride = 2帧**：

**（1）手部运动学特征（126维/帧）**

| 特征 | 维度 | 计算方式 |
|------|------|----------|
| 原始关键点 | 21×3=63 | MediaPipe直接输出 (x,y,z)，归一化至[0,1] |
| 相对手掌中心 | 21×3=63 | 每点减去手腕点(landmark[0])坐标 → 手势姿态不变性 |

**（2）手-零件空间关系特征（可变维）**

| 特征 | 维度 | 计算方式 |
|------|------|----------|
| 手-零件距离 | N_parts×2 | 手掌中心(landmark[0])到每个零件检测框中心的欧氏距离 |
| IoU特征 | N_parts×1 | 手部检测框与每个零件框的IoU（判断接触） |
| 最近零件ID | 1 | argmin(手-零件距离) |

其中 N_parts 为当前帧YOLO检测到的零件数量（通常3-8个）。
为统一输入维度，取距离最近的 **Top-4** 个零件，不足则补零 → 固定 12维。

**（3）手指开合度特征（2维）**

| 特征 | 计算方式 | 用途 |
|------|----------|------|
| 拇指-食指距离 | ‖landmark[4] - landmark[8]‖ | 判定抓取/释放（距离小→抓取，大→释放） |
| 抓取状态 | threshold(距离, 0.05) → {0, 1} | 二值特征辅助判断 |

**（4）帧间运动特征（126维）**

对原始关键点计算一阶和二阶差分：

| 特征 | 维度 | 计算方式 |
|------|------|----------|
| 速度 | 21×3=63 | v(t) = p(t) - p(t-1) |
| 加速度 | 21×3=63 | a(t) = v(t) - v(t-1) |

---

**特征汇总（每帧）**：

| 特征组 | 维度 |
|--------|------|
| 手部关键点（相对坐标） | 63 |
| 手部关键点（原始坐标） | 63 |
| 手-零件空间关系 | 12 |
| 手指开合度 | 2 |
| 帧间速度 | 63 |
| 帧间加速度 | 63 |
| 零件类别嵌入 (YOLO cls embedding) | 32 |
| **合计（单帧特征向量）** | **~298维** |

滑动窗口 16 帧 → 模型输入形状：**[batch, 16, 298]**

#### 4.2.5 时序模型架构

**主模型：Bi-LSTM（推荐首选）**

```
Input: [batch_size, 16, 298]
        │
        ▼
┌─ PositionalEncoding (learnable, dim=298) ─┐
│  (帮助 LSTM 感知帧之间的绝对/相对位置)     │
└──────────────────┬────────────────────────┘
                   │
                   ▼
┌─ Bi-LSTM Layer 1 ─────────────────────────┐
│  input_size=298, hidden_size=128          │
│  num_layers=2, bidirectional=True        │
│  dropout=0.2 (层间)                       │
│  输出: [batch, 16, 256]                   │
└──────────────────┬────────────────────────┘
                   │
                   ▼
┌─ Temporal Attention (Scaled Dot-Product) ─┐
│  Q=W_q·H, K=W_k·H, V=W_v·H               │
│  Attention(Q,K,V)=softmax(QK^T/√d_k)V     │
│  → 加权池化，突出关键帧贡献                  │
│  输出: [batch, 256]                       │
└──────────────────┬────────────────────────┘
                   │
                   ▼
┌─ FC Block ────────────────────────────────┐
│  Linear(256→128) + BatchNorm + ReLU       │
│  Dropout(0.3)                             │
│  Linear(128→64) + BatchNorm + ReLU        │
│  Dropout(0.3)                             │
│  Linear(64→7) + Softmax                   │
│  输出: [batch, 7]  (7类动作概率)           │
└───────────────────────────────────────────┘
```

**参数量估算**：
- LSTM部分：~400K
- Attention + FC：~100K
- 总计：~500K，显存占用 < 2MB（FP16）
- 单次推理延迟：~3-5ms（GPU），~8-15ms（CPU）

**备选方案：Transformer Encoder**

当装配动作高度依赖长距离时序依赖（如 > 32帧的慢速旋拧动作），可切换为：

```
Input: [batch, 16, 298]
        │
        ▼
Linear Projection (298 → 256)
        │
        ▼
Positional Encoding (sinusoidal, fixed)
        │
        ▼
┌─ Transformer Encoder × 4 layers ──────────┐
│  d_model=256, nhead=4, dim_ff=512        │
│  dropout=0.1, activation=GELU            │
│  输出: [batch, 16, 256]                   │
└──────────────────┬────────────────────────┘
                   │
                   ▼
Global Average Pooling → [batch, 256]
                   │
                   ▼
FC Head (256→128→64→7) + Softmax
```

参数量 ~1.2M，推理延迟 ~8-12ms（GPU）。

**切换策略**：训练两个模型，根据笔型复杂度在配置文件中指定使用LSTM或Transformer。

#### 4.2.6 训练策略

**数据增强（时序层面）**：

| 增强方法 | 参数 | 说明 |
|----------|------|------|
| 时间裁剪 | crop_ratio=[0.8, 1.0] | 随机截取原始序列的80%-100%，保持动作完整性 |
| 时间缩放 | speed=[0.8, 1.25] | 模拟不同操作速度（线性插值采样） |
| 关键点抖动 | noise_std=0.005 | 对关键点坐标添加高斯噪声（模拟检测误差） |
| 水平翻转 | p=0.5 | 仅当相机镜像安装时使用 |
| 手部平移 | shift=±0.02 | 关键点整体平移（模拟手部位置变化） |
| Mixup | α=0.2 | 两个样本的线性插值混合 |

**损失函数**：

```
L_total = L_CE + λ1 * L_center + λ2 * L_smooth

L_CE      : 交叉熵损失（动作分类主损失）
L_center  : Center Loss（增大类间距离，减小类内距离）λ1=0.003
L_smooth  : 时序平滑损失（相邻帧预测标签一致性）λ2=0.01
```

**训练超参数**：

| 参数 | 值 |
|------|-----|
| 优化器 | AdamW |
| 学习率 | 1e-3 (初始), cosine annealing |
| 权重衰减 | 1e-4 |
| Batch Size | 64 |
| Epochs | 120 |
| 早停 | patience=15 (val_loss) |
| 学习率预热 | 前5个epoch线性warmup |
| 混合精度 | AMP (FP16) |

**类别不平衡处理**：
- "闲置(Idle)"类别样本量可能是其他类别的10倍+
- 采用 Focal Loss 替代标准交叉熵：`FL(p_t) = -(1-p_t)^γ * log(p_t)`，γ=2.0
- 或在采样时使用 weighted RandomSampler

#### 4.2.7 推理部署优化

```python
# 推理流程 - 滑动窗口在线预测
class ActionRecognizer:
    def __init__(self, window_size=16, stride=2):
        self.buffer = deque(maxlen=window_size)  # 特征缓冲
        self.window_size = window_size
        self.stride = stride
        self.frame_counter = 0

    def process_frame(self, hand_landmarks, object_boxes):
        # 1. 特征提取
        features = self.extract_features(hand_landmarks, object_boxes)
        self.buffer.append(features)

        # 2. 每 stride 帧推理一次（降低计算量）
        self.frame_counter += 1
        if self.frame_counter % self.stride != 0:
            return self.last_prediction

        # 3. 构建输入窗口
        if len(self.buffer) < self.window_size:
            # 不足16帧时复制首帧padding
            window = self._pad_window()
        else:
            window = np.array(list(self.buffer))

        # 4. ONNX推理
        input_tensor = window[np.newaxis, ...].astype(np.float32)
        logits = self.onnx_session.run(None, {'input': input_tensor})[0]
        probs = softmax(logits)
        pred_class = np.argmax(probs)
        confidence = probs[pred_class]

        self.last_prediction = (pred_class, confidence)
        return self.last_prediction
```

#### 4.3.1 SOP形式化建模

每条SOP规则定义为一个**有限状态机（FSM）**，包含以下要素：

```python
@dataclass
class SOPStep:
    id: str                          # 步骤ID, e.g. "S2_spring"
    name: str                        # 步骤名称, e.g. "安装弹簧"
    expected_action: str             # 期望动作, e.g. "Insert"
    target_part: str                 # 目标零件, e.g. "spring"
    parent_part: str                 # 装配到哪个零件, e.g. "barrel"
    timeout_ms: int                  # 超时阈值(ms), e.g. 5000
    required_parts_present: List[str] # 此步骤前必须出现的零件
    optional: bool = False           # 是否为可选步骤

@dataclass
class SOPTemplate:
    model_name: str                  # 笔型名称, e.g. "GelPen_0.5mm"
    version: str                     # SOP版本号
    steps: List[SOPStep]             # 有序步骤列表
    initial_parts: List[str]         # 初始状态下工作台应有的零件
    final_parts: List[str]           # 完成时应有的零件/组件
    state_graph: Dict[str, List[str]] # 状态转移图 (允许的转移)
```

**典型笔装配SOP状态机示例**：


#### 4.3.2 实时匹配算法

```
算法流程：每收到一个新的动作预测 (action_label, confidence, frame_ts)

┌──────────────────────────────────────────────────────────┐
│  Step A: 动作有效性过滤                                   │
│  if confidence < MIN_CONFIDENCE (0.6):                   │
│      → 丢弃此预测（视为噪声），返回當前状态                │
│  if action_label == "Idle":                              │
│      → 更新空闲计时器，检查超时。返回當前状态              │
│  if action_label == last_action AND not repeated_action: │
│      → 去重（同一动作的连续重复预测），返回當前状态          │
├──────────────────────────────────────────────────────────┤
│  Step B: SOP匹配                                          │
│  expected = SOP.expected_action(current_state)            │
│  if action_label == expected:                            │
│      → ✓ 匹配成功：current_state → next_state            │
│      → 记录 step_completion_time                         │
│      → 重置 timeout_timer                                │
│  elif action_label in SOP.valid_skips(current_state):    │
│      → △ 跳步（如跳过可选步骤）: 跨过当前步骤             │
│      → 记录 warning（跳步记录）                           │
│  else:                                                    │
│      → ✗ 顺序异常：触发 SequenceError 告警                │
├──────────────────────────────────────────────────────────┤
│  Step C: 零件校验                                         │
│  current_parts = object_detector.get_current_parts()     │
│  required = SOP.required_parts(current_state)             │
│  if not all(p in current_parts for p in required):       │
│      → ✗ 零件缺失/错误：触发 PartError 告警               │
├──────────────────────────────────────────────────────────┤
│  Step D: 超时检查                                         │
│  if time_in_current_state > SOP.timeout(current_state):  │
│      → ✗ 超时：触发 TimeoutError 告警                     │
└──────────────────────────────────────────────────────────┘
```

#### 4.3.3 DTW时序对齐（离线阶段）

当需要为**新笔型自动生成SOP模板**时，使用DTW对不同操作员的演示视频进行时序对齐：

```
输入: 3-5段标准装配演示视频的动作序列
输出: 对齐后的标准SOP步骤序列

步骤:
1. 对每段视频运行动作识别 → 获得动作标签序列 S1, S2, ..., Sk
2. 使用 DTW 对齐所有序列对之间的时间差异
3. 在每个对齐位置采用多数投票确定标准动作
4. 统计每步的时间分布（均值±2σ作为超时阈值）
5. 输出 SOPTemplate（含步骤、动作、零件、时间阈值）
```

**DTW相似度作用**：
- 评估操作员动作序列与标准SOP的整体偏离程度
- 偏离超过阈值（DTW distance > τ）标记为"需人工复核"
- 用于发现新手操作员与熟练工的差距

### 5.3 判断逻辑伪代码

```python
def detect_sop_compliance(frame_sequence, sop_template):
    state = sop_template.initial_state
    detected_steps = []
    anomalies = []

    for frame in frame_sequence:
        # 1. 检测当前帧中的零件和手部
        objects = object_detector.detect(frame)
        hand_pos = hand_detector.detect(frame)

        # 2. 对比历史帧，识别动作
        action = action_classifier.classify(
            object_trajectory, hand_trajectory)

        # 3. 检查当前动作是否符合SOP期望
        expected = sop_template.expected_action(state)
        if action != expected:
            if action in sop_template.valid_next_actions(state):
                # 跳过步骤或替代动作
                state = sop_template.transition(state, action)
            else:
                # 异常：顺序错误
                anomalies.append(SequenceError(action, expected))
        else:
            state = sop_template.transition(state, action)
            detected_steps.append((action, timestamp))

        # 4. 检查零件正确性
        part_check = part_validator.validate(
            objects, sop_template.required_parts(state))
        if not part_check.passed:
            anomalies.append(PartError(part_check.detail))

        # 5. 检查超时
        if state.duration > sop_template.timeout(state):
            anomalies.append(TimeoutError(state))

    # 6. 最终完整性检查
    if not sop_template.all_steps_completed(detected_steps):
        anomalies.append(MissingStepError(
            sop_template.missing_steps(detected_steps)))

    return DetectionResult(
        passed=(len(anomalies) == 0),
        detected_steps=detected_steps,
        anomalies=anomalies,
        confidence=calculate_confidence(detected_steps)
    )
```

#### 2.2 动作识别模型（Bi-LSTM，方案A核心）

| 周次 | 任务 | 具体内容 |
|------|------|----------|
| W4 | 特征提取Pipeline | 实现MediaPipe手部关键点 + YOLO零件检测 → 特征工程（298维/帧） |
| W4-W5 | 特征预处理 | 对每段标注视频，按16帧滑动窗口（stride=2）提取特征序列，构建训练样本 |
| W5 | Bi-LSTM训练 | 在动作标注数据上训练 Bi-LSTM 模型（详见4.2.5节架构） |
| W5 | 超参调优 | window_size={8,16,32}, hidden_size={64,128,256}, num_layers={1,2,3} |
| W5-W6 | 迭代优化 | 基于验证集反馈调整：<br>· 分析混淆矩阵，定位易混动作对<br>· 针对性增强弱类样本<br>· 调整Focal Loss γ参数 |
| W6 | Transformer对比 | 训练Transformer Encoder版本作为对照，对比精度/延迟 |
| W6 | 模型评估 | 动作分类 Accuracy > 92%，动作Recall (per class) > 88% |
| W6 | 模型导出 | PyTorch → ONNX → TensorRT（详见4.2.7节） |

**训练脚本骨架**：
```python
# train_action_model.py
from torch.utils.data import DataLoader
from action_dataset import ActionSequenceDataset
from action_model import BiLSTMActionClassifier

# 1. 数据加载
train_ds = ActionSequenceDataset(
    annotations_path="data/action_labels.json",
    features_path="data/features/",
    window_size=16, stride=2, augment=True
)
train_loader = DataLoader(train_ds, batch_size=64, shuffle=True, num_workers=4)

# 2. 模型初始化
model = BiLSTMActionClassifier(
    input_dim=298, hidden_dim=128, num_layers=2,
    num_classes=7, dropout=0.2, bidirectional=True
)
model = model.cuda()

# 3. 训练循环
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-4)
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=120)
criterion = FocalLoss(gamma=2.0)  # 处理类别不平衡

for epoch in range(120):
    for batch in train_loader:
        features, labels = batch  # features: [B, 16, 298]
        logits = model(features.cuda())
        loss = criterion(logits, labels.cuda())
        loss.backward()
        optimizer.step()
    scheduler.step()

# 4. 导出ONNX
torch.onnx.export(model, dummy_input, "action_model.onnx", opset_version=14)
```

### 8.6 前端部署架构

```
                     Nginx (反向代理)
                           │
          ┌────────────────┼────────────────┐
          │                │                │
          ▼                ▼                ▼
    /api/*            /ws/*            /* (静态资源)
    FastAPI           FastAPI          Vue.js SPA
    (REST)            (WebSocket)      (dist/ 目录)
          │                │
          └────────┬───────┘
                   │
          ┌────────┴────────┐
          ▼                 ▼
    PostgreSQL           Redis
```

- Vue.js 构建产物 (`dist/`) 作为静态资源由 Nginx 直接 serve
- `/api/*` 反向代理到 FastAPI 后端
- `/ws/*` 升级为 WebSocket 连接，由同一 FastAPI 实例处理
- 大屏使用 Chrome Kiosk 模式全屏运行，开机自启
